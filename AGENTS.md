# finwise — Agent Briefing

> Read before every interaction. This file holds only the rules that are already in force; the stack,
> the commands and the gates are added as the project gains them.

> **What it is:** a personal finance app for one person, over the SQLite ledger that
> [pluggy-sync](https://github.com/gabrielassisxyz/pluggy-sync) collects. The numbers are someone's
> money: a wrong total or a silently dropped transaction is the failure that matters.

## Tracker
- Work is tracked with `br` in `.beads/` (`br ready`, `br show <id>`). A bead is self-contained:
  implement from it, not from an external plan.

## Merging
- An agent merges its own pull request once the repository's gate is green locally and every check
  on the pull request is green; nobody waits for a human to press merge. While the repository has
  no gate and no checks, the pull request body says how the change was verified. Work still goes
  through a branch, atomic commits and a pull request whose body carries the why.

## Stack & Commands
- **Frontend:** `web/` is Vue 3, Vite and TypeScript, with vue-router and Pinia. Styles are plain
  CSS in each component, built on CSS variables. The interface reaches its backend through
  `FinwiseApi`, and which implementation it gets is decided when it is built:
  - `vite build` is the build for real use: `web/src/api/http` posts every contract method to its
    `/api/<domain>/<method>` route. It contains neither the in-memory stand-in nor its dataset.
  - `vite build --mode prototype` is the same interface on the stand-in, `web/src/api/fake`, which answers
    with the design prototype's dataset. The parity scripts build in this mode.
  - Every failure of the API ends in `web/src/api/failures.ts`, wired to Vue's error handler and to the
    window's `unhandledrejection`; call sites do not catch. A refused write toasts that the app is read-only
    and bumps the revision counter, a `locked` answer brings the PIN screen back, and any other failure
    toasts with "Tentar de novo".
- **Install:** `npm --prefix web ci`
- **Run:** `npm --prefix web run dev` runs the stand-in; its PIN is `123456`.
  `VITE_FINWISE_STATE=fresh` starts the stand-in as a fresh install (the bank's records and nothing the
  person authors) and `VITE_FINWISE_STATE=empty` as an empty ledger; only the dev server reads it.
  `npm --prefix web run dev:backend` runs the HTTP client and proxies `/api` to `127.0.0.1:8080`.
- **Test:** `npm --prefix web test`
- **Gate:** `bin/ci` (secret scan, shellcheck, tokens current, no raw design value, contract manifest
  current, types, tests, build, and a bundle check that builds both modes and fails unless the build for
  real use lacks a string only the prototype dataset holds while the prototype build has it). It is the
  exact thing CI runs. Run it before a pull request.
- **Contract:** `internal/contract/contract.json` describes every method of `FinwiseApi` (route, class,
  argument and result schemas, error envelope) for readers that are not TypeScript. It is generated by
  `npm --prefix web run contract`, versioned, never edited by hand; changing a contract type or
  `web/src/api/contract/classification.ts` means regenerating it. A new method is classified there.
  A field the ledger cannot always answer is nullable in the contract and a screen shows its absence
  (a dash for an unknown figure, a sentence for an empty list); a zero is for a figure that is truly zero.
- **Parity:** `npm --prefix web run parity` builds in prototype mode and measures every ported screen
  against the design. It is not part of `bin/ci` because the measurement depends on the browser build;
  run it for any change that touches a screen and put its output in the pull request body.
- **Backend:** Go, one module at the repository root (`github.com/gabrielassisxyz/finwise`, version in
  `go.mod`), driver `modernc.org/sqlite`. `internal/ledger` reads pluggy-sync's `pluggy-snapshot.db`
  read-only, reopening it on every call; `ledgertest` beside it builds invented snapshots for tests.
  `internal/money` holds amounts as integer cents and `internal/brday` turns Brazil days into UTC
  bounds. `go test ./...` is the test command and `bin/ci` runs it with `gofmt`, `go vet` and
  `go build`. A query that mirrors one in pluggy-sync's README cites its lines in a comment.
- **Serve:** `finwise serve` is the HTTP backend over the ledger snapshot. It is read-only: every write
  and evaluation of the contract is refused with `read_only`, and every method except `session.status`
  and `session.unlock` needs the session cookie. The PIN is never stored; make its hash and start:

  ```
  printf '%s\n' 123456 | go run ./cmd/finwise hash-pin          # prints pbkdf2-sha256$...
  FINWISE_PIN_HASH='<that string>' go run ./cmd/finwise serve --ledger <snapshot.db> --dev-insecure-cookie
  ```

  Settings: `--listen` / `FINWISE_LISTEN` (default `127.0.0.1:8080`), `--ledger` / `FINWISE_LEDGER`,
  `FINWISE_PIN_HASH` (required), `FINWISE_SESSION_TTL` (idle expiry, default `12h`).
  `--dev-insecure-cookie` is for plain HTTP only: without it the cookie is `__Host-` prefixed and
  `Secure`, which a browser may refuse over HTTP. A missing snapshot does not stop the server; reads
  answer `ledger_unavailable`. A read handler is registered in `internal/api` with
  `Registry.Register("domain.name", handler)`, one `register<Domain>` function per domain listed in
  `domainRegistrations`; `pendingReads` in `reads_pending_test.go` lists the reads still without one.

## Design
- The design arrives as an HTML prototype. It is a reference, never code to copy: `design/README.md`
  says how it becomes tokens, reference screenshots and screens.
- `design/tokens/finwise.tokens.json` is the only place a color, a type size, a radius, a shadow or
  a step of the spacing scale is written. `npm --prefix web run tokens` builds
  `web/src/styles/tokens.css` from it; that file is versioned and never edited by hand.
- A component references tokens and nothing else for those values. A one-off that is not a design
  decision carries a `token-exempt: <reason>` comment on its line.
- A screen is ported when its states in `web/scripts/parity/states.mjs` pass on both viewports.
  A screen being built is fixed in the component or in the tokens, never by raising the limit.
- Interface text is Brazilian Portuguese. Everything else in the repository is English.

## Tests
- Every feature is born with a test; every bugfix with a regression test.
- Tests run with one command, no manual setup, no credential.
- The backend is faked at the API boundary with `createFakeApi`, not with an inline stub.
- A screen test that needs the backend to refuse wraps `createFakeApi` with `readOnlyApi`
  (`web/src/test/readOnly.ts`), which rejects every `write` and `evaluate` method with `read_only`. Only the
  HTTP client's own tests stub `fetch`.
- Fixtures are invented. Nothing derived from a real account is committed.
- A real ledger is a person's whole financial history and this repository is public. A real snapshot
  may be opened read-only to check a schema, the keys of a JSON column or a count; no value from it
  (amount, description, name, document, id) is ever printed, logged, copied, committed or pasted, and
  a row count, though it may be shown to the person running the test, goes into no file and no pull
  request. The one test that touches it runs only when `FINWISE_LEDGER_SNAPSHOT` names a file, and
  logs counts only.
